# MeetPoint 제품 정의

## 문서 상태

- **확정**: 현재 제품은 친구 3~6명이 모임의 시간과 장소를 정하는 문제에 집중한다. 호스트도 모임 참가자로 간주하며 자신의 조건과 응답을 제출할 수 있다.
- **확정**: 호스트가 2~5개의 시간-장소 후보를 만들고, 모든 참가자의 조건과 후보별 응답을 바탕으로 반복 가능한 점수와 근거를 보여준다.
- **미결정**: 향후 지원할 모임 유형, 계정 정책, 지도·이동시간 데이터 공급자, 제품 성과를 측정할 외부 지표는 별도로 결정한다.

## 1. 해결하려는 문제

친구들이 모임을 정할 때 각자 가능한 시간, 후보별 체감 이동 부담, 예산, 식당·분위기 선호가 다르다. 단체 채팅에서 “저는 아무 때나 괜찮아요”라고 말하거나 후보에 투표하는 방식만으로는 다음 문제를 해결하기 어렵다.

- 시간은 맞지만 한 명이 특정 장소의 이동을 매우 어렵게 느낄 수 있다.
- 장소는 모두에게 가까워도 한 명의 예산을 넘을 수 있다.
- 가장 많은 표를 받은 후보가 불참자의 필수 조건을 위반할 수 있다.
- 후보가 모든 조건을 만족하지 못할 때 무엇을 양보해야 하는지 알 수 없다.
- 같은 입력으로 다시 계산했을 때 결과가 달라지면 방장이 결과를 신뢰하기 어렵다.

MeetPoint는 투표 수를 세는 대신, 참가자별 조건을 후보에 대입하고 후보별 만족도·충돌 조건·응답 누락을 함께 보여주는 의사결정 도구다.

## 2. 핵심 사용자

### 호스트

모임 방을 만들고 초대 링크 또는 방 코드를 공유하는 사람이다. 후보 시간과 장소를 등록하고 계산을 요청하며, 결과를 확인한 뒤 최종 후보를 확정한다. 로그인 계정은 없으므로 방 생성 때 발급받은 호스트 전용 접근 토큰으로 호스트 작업을 수행한다.

### 참가자

방 코드로 방에 입장하여 표시 이름, 가능한 시간, 예산, 선호 조건을 입력한다. 각 후보에 대해 가능한지와 이동 부담(`편함·보통·어려움`)을 직접 응답하고 필요하면 다시 수정한다. 호스트도 참가자로서 같은 조건 입력을 할 수 있다.

### 참여자 수

한 방의 활성 참가자는 호스트를 포함하여 3~6명으로 제한한다. 방은 호스트만 있는 상태로 만들어질 수 있지만, 3명 미만인 상태에서는 최종 계산 및 확정을 진행하지 않는다.

## 3. 실제 사용 상황

예를 들어 토요일 저녁에 네 명이 만나려는 상황을 생각한다.

- 민수는 18시 이후에만 가능하고, 후보 A·B의 이동 부담을 `보통` 이하로 평가하며 3만 원 이하를 선호한다.
- 지수는 19시 이후가 편하지만 후보 B의 이동 부담을 `어려움`으로 평가하고, 실내 조용한 장소를 원한다.
- 현우는 18시부터 가능하지만 채식 메뉴가 있어야 한다.
- 호스트는 세 가지 시간과 장소 조합을 제안한다.

후보 A는 시간이 모두에게 가능하고 평균 점수가 높지만 현우의 선호 태그가 없다. 후보 B는 현우에게 좋지만 지수의 이동 부담이 `어려움`이고 민수의 가능 시간이 `MAYBE`다. MeetPoint는 후보 A를 단순히 1위로 표시하는 데 그치지 않고, 각 참가자의 점수와 “지수의 이동 부담”, “현우의 필수 선호 누락” 같은 이유를 함께 표시한다. 세 후보 모두 필수 조건을 충족하지 못하면 “완전 일치 후보 없음”을 명시하고 충돌 조건이 가장 적은 후보를 비교 대상으로 남긴다.

## 4. 핵심 가치

1. **조건을 반영한 비교**: 시간·이동 부담·예산·선호를 같은 후보에 대해 일관된 규칙으로 비교한다.
2. **설명 가능한 결과**: 후보의 총점뿐 아니라 참가자별 세부 점수, 충돌 조건, 응답 누락을 보여준다.
3. **반복 가능한 계산**: GPT의 판단이나 투표 순서에 의존하지 않고 Rust Solver의 고정된 규칙과 정책 버전으로 같은 입력에 같은 결과를 만든다.
4. **타협 지점의 가시화**: 모두를 만족시키는 후보가 없어도 어떤 조건이 충돌하고 무엇을 양보하는지 확인할 수 있다.
5. **빠른 합의**: 채팅에서 조건을 여러 번 묻고 정리하는 시간을 줄이고, 방장이 최종 결정을 내릴 근거를 한 화면에 모은다.

## 5. 현재 제품 범위

### 포함하는 기능

- 익명 방 생성, 6자리 방 코드와 초대 링크 발급
- 호스트 및 참가자의 표시 이름 기반 입장
- 2~5개의 시간-장소 후보 등록·수정·보관 처리
- 참가자별 개인 조건 입력
  - 가능한 시간대
  - 1인 기준 최대 예산
  - 필수·선호·회피 장소 태그
- 참가자의 후보별 이동 부담 입력
  - `편함`, `보통`, `어려움` 중 하나
- 참가자의 후보별 응답 제출 및 수정
- 호스트의 후보 점수 계산 요청
- 후보별 총점, 참가자별 점수, 응답 커버리지, 계산 근거와 충돌 조건 표시
- 조건을 모두 만족하는 후보가 없는 경우의 별도 표시
- 호스트의 최종 후보 확정과 참가자의 확정 결과 조회
- 확정 후 재검토를 위한 결과 재계산 및 결정 변경 흐름

### 장소와 이동을 다루는 방법

장소는 이름과 주소를 호스트가 직접 입력한다. 지도 검색, 좌표 계산, 실제 교통 경로 계산은 포함하지 않는다. 참가자는 각 후보에 대해 이동 부담을 `편함(EASY)`, `보통(NORMAL)`, `어려움(HARD)` 중 하나로 직접 입력한다. Rust Solver는 이 주관적 응답을 고정 점수로 변환할 뿐이며, 주소에서 이동 거리나 시간을 추정하지 않는다.

## 6. 현재 제품에 포함하지 않는 기능

- 이메일·소셜 로그인, 사용자 계정, 친구 목록, 권한 관리 시스템
- 지도 검색, 지오코딩, 좌표 기반 거리 계산, 실시간 교통량, 실제 이동시간 API
- 결제, 예약, 장소 영업시간 자동 확인
- 채팅, 댓글, 파일 첨부, 모임 후 평가
- 푸시·이메일·문자 알림
- 실시간 동시 편집과 실시간 점수 스트리밍
- 반복 모임, 회사 회식·행사 등 6명을 넘는 모임 유형
- 자연어 조건을 바로 점수로 해석하는 GPT 기반 계산
- 투표 수만으로 순위를 정하는 기능
- Next.js API Route 또는 Server Action 기반 백엔드 기능

## 7. 성공 기준

### 기능 수용 기준

- 호스트가 방을 만들고 방 코드 또는 링크를 공유할 수 있다.
- 호스트가 2~5개의 시간-장소 후보를 등록할 수 있다.
- 호스트 포함 3~6명의 참가자가 각자의 조건을 저장할 수 있다.
- 모든 활성 후보에 대해 참가자가 응답하면 계산 결과를 요청할 수 있다.
- 결과 화면에서 후보별 총점, 참가자별 점수, 점수 근거, 충돌 조건, 응답 커버리지를 확인할 수 있다.
- 완전 일치 후보가 없을 때도 이를 숨기지 않고 표시하며, 호스트가 충돌을 확인한 뒤 후보를 확정할 수 있다.
- 같은 입력 스냅샷과 같은 `policyVersion`으로 다시 계산하면 순위와 점수가 동일하다.
- 조건 또는 응답이 수정되면 이전 계산 결과가 최신 결과가 아님을 표시한다.

### 제품 검증 목표

위 기능 수용 기준은 **확정**한다. 실제 사용자 수, 재방문율, 평균 결정 시간, 만족도 같은 정량 목표는 사용성 테스트 후 정한다. 숫자를 임의로 정해 제품 성공으로 포장하지 않는다.

## 8. 단순 투표 서비스와의 차이

| 비교 항목 | 단순 투표 | MeetPoint |
| --- | --- | --- |
| 입력 | 후보에 대한 찬반 또는 표 | 개인 조건과 후보별 응답 |
| 참가자 차이 | 모든 표를 같은 단위로 취급 | 각자의 시간·이동·예산·선호 조건 반영 |
| 결과 | 득표수가 많은 순서 | 규칙 기반 후보 점수와 참가자별 breakdown |
| 소수 의견 | 득표에 묻힐 수 있음 | 어떤 필수 조건이 충돌했는지 표시 |
| 완전 일치 없음 | 보통 1위만 표시 | `NO_FULL_MATCH` 상태와 충돌 조건 표시 |
| 설명 | 결과의 이유가 불명확 | 점수 구성, 입력값, 근거 템플릿 제공 |
| 재계산 | 표 상태에 따라 결과가 바뀔 수 있음 | 입력 스냅샷과 정책 버전으로 결정적 계산 |
| 최종 결정 | 자동으로 1위 확정될 수 있음 | 호스트가 근거를 확인하고 명시적으로 확정 |

## 확정 사항과 미결정 사항 요약

- **확정**: MeetPoint는 3~6명 모임의 조건 기반·설명 가능한 후보 비교 서비스다. 점수 계산은 Rust Solver가 담당하고 GPT는 점수 계산에 사용하지 않는다.
- **확정**: 현재 제품에는 계정, 지도 API, 실시간 기능, 알림, 투표 중심 UX를 넣지 않는다.
- **미결정**: 사용성 검증 후 점수 가중치 조정 방식, 모임 유형 확장, 정량적인 제품 KPI와 보존 기간을 결정한다.
